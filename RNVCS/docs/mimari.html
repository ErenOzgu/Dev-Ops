1 Sistem ne yapar?

Sahadaki dokunmatik "muhabere panelleri", bir merkez sunucu (CORE) üzerinden birbirini arar; çatal arama, konferans, sesli mesaj yapar. INTERKOM ve IP Horn cihazları da aynı sisteme bağlanır. Yöneticiler kullanıcı/panel/yetki tanımlarını bir web arayüzünden (Bakım/Kontrol Terminali) yapar.

Üç yazılım bileşeni var:

🖥️ core Go

:8091 · CORE sunucusunda

REST API + web yönetim arayüzü. PostgreSQL'deki tanımları Asterisk config dosyalarına yansıtır, login/oturum yönetir. İkili adı: rnvcs-yonetim-servisi.

📞 panel-backend Go

:8090 · her panel cihazında

Panelin yerel "telefon motoru": gerçek SIP user agent (REGISTER/INVITE/BYE), RTP/G.711 ses köprüsü (arecord/aplay), ses seviyesi, ses aygıtı keşfi.

🪟 panel-app HTML/JS

kiosk tarayıcı · tek dosya

Operatör arayüzü: login, dialpad, hızlı arama, gelen/aktif çağrı, konferans, sesli mesaj, "Sayfam" kutuları. TR / AZ / EN.

Destekleyici parçalar: migrations/ (PostgreSQL şeması), scripts/ (kurulum/deploy/rollback/smoke test), infra/systemd/, .gitea/workflows/ (CI/CD), docs/.

2 Topoloji

Kaba hatlarıyla: panel cihazı iki şeyle konuşur — yerel backend'i (ses/çağrı) ve merkezî CORE (giriş, kısayol, sesli mesaj). CORE da PostgreSQL ve Asterisk'i sürer.

HTTP / REST SIP / RTP (ses) dahili (DB / dosya / AMI)
Not INTERKOM / IP Horn cihazları kendi SIP firmware'leriyle doğrudan Asterisk'e bağlanır. Redis kurulu ama hiçbir bileşen kullanmıyor. Uzak sahalarla IAX2 trunk (:4569) tanımlanabiliyor ama dialplan'i henüz yazılmıyor (özellik yarım).

3 Dört temel tasarım kararı

Kodun her yerinde karşınıza çıkan, "neden böyle yapılmış" sorusunun cevabı olan kararlar:

🗄️
Tek gerçek kaynak: PostgreSQL Panel, kullanıcı, SIP hesabı, ring group önce DB'ye yazılır; sonra ilgili Asterisk config dosyasına blok eklenir ve asterisk -rx "… reload" çağrılır. Asterisk realtime kullanılmıyor, dosya üretiliyor.
📦
Sıfır harici Go bağımlılığı İzole ağda Go modül proxy'sine erişim garanti olmadığından iki Go modülü de yalnız stdlib kullanır. Sonuç: DB'ye psql alt süreciyle erişim, elle yazılmış PBKDF2, elle yazılmış AMI / SIP / RTP / G.711 yığını.
👤
SIP kimliği kullanıcıya ait Operatör hangi panelden girerse girsin, backend kendi sip_username/sip_password'üyle REGISTER olur. device_type='PANEL' kayıtları SIP register olmaz — sadece yetki etiketi + sesli mesaj kutusu. INTERKOM/IP_HORN ise gerçek donanım, kendi endpoint'ini alır.
🔑
Oturumlar bellek-içi Bearer token'lar auth.SessionStore map'inde tutulur; servis restart olunca herkes yeniden login olur. 12 saat sabit ömür, kullanıcı başına tek aktif oturum.

4 core — Yönetim Servisi

Başlangıç akışı (core/main.go)

  1. Zorunlu env: RNVCS_DB_DSN, RNVCS_PROVISIONING_KEY — yoksa durur.
  2. DB bağlantı testi (SELECT 1), açılışta panel_session_history tablosunu IF NOT EXISTS ile yaratır.
  3. Alt komut: create-admin <kullanıcı> <şifre> → ilk ADMIN'i yaratıp çıkar.
  4. Rotaları bağlar, arka plan konferans izleyicisini (confwatch) başlatır, :8091 dinler. / yolunda gömülü Bakım Terminali HTML'i sunulur.

Paket haritası

PaketSorumluluk
internal/pgHer sorgu için bir psql süreci çalıştırır, çıktıyı TAB ile böler. EscapeLiteral tek tırnağı ikiler. Transaction yok.
internal/authPBKDF2-HMAC-SHA256 (210k iterasyon, rastgele salt) parola hash'i; bellek-içi oturum deposu.
internal/apiTüm HTTP handler'ları: login, users, panels, permissions, ring_groups, speed_dials, sayfam_tiles, iax_trunks, voicemail, call_records, conference, events, panel_config.
internal/pjsipPJSIP endpoint/auth/aor bloklarını yazar — idempotent (işaretli blok: eskiyi siler, yenisini yazar). RemoveEndpoint var.
internal/dialplan[rnvcs-panels] extension blokları (direkt arama, ring group, cihaz) — çoğu append (idempotent değil).
internal/confbridgeConfBridge() oda extension'ı — idempotent (işaretli blok).
internal/iaxconf · voicemailIAX2 trunk blokları; voicemail mailbox tanımları (RewriteAll tüm dosyayı DB'den yeniden üretir).
internal/amiHam TCP AMI istemcisi: Login, Originate, ConfbridgeList/Kick/PlayFile, event dinleme.
internal/confwatchAMI event'lerini dinler; konferansta tek kişi kalınca anons çalıp odayı kapatır.

6 Kritik akışlar

Operatör login (panelden)

panel_app
POST CORE/api/login — kullanıcı adı, şifre, panel_code gönderir
core
Kullanıcıyı çeker → enabled? → PBKDF2 doğrular → can_login panellerini listeler → token üretir (eski oturum düşer) → LOGIN event + oturum geçmişi yazar
panel_app
POST BACKEND/api/session — CORE url + token iletir
backend
CORE'dan SIP kimliğini çeker → kalıcı UDP soket açar → Asterisk'e REGISTER (401 → MD5 digest → 200) → 0.7×Expires'ta yeniler
panel_app
1 sn'de bir çağrı durumu, 15 sn'de bir oturum geçerliliği yoklar (401 → otomatik logout)

SIP hesabı atama (ADMIN, Bakım Terminali'nden)

core
UPDATE users SET sip_username, sip_password (düz metin)
core
pjsip.AppendEndpoint → config + "pjsip reload"
core
dialplan.AppendDirectExtension → kullanıcı doğrudan aranabilir + "dialplan reload"

Gelen çağrı (panel tarafı)

Asterisk→backend
INVITE (SDP) gelir → meşgulse 486, SDP yoksa 488; değilse 100 Trying + 180 Ringing, durum ringing
panel_app
Durumu "ringing" görür → gelen çağrı ekranı + Web Audio ile çalma sesi
backend
Operatör "Cevapla" → RTP soketi aç, 200 OK + SDP (PCMU) → ses köprüsü: arecord → μ-law → RTP → μ-law → aplay
backend
BYE gelince → 200 OK, durum sıfırlanır (arecord/aplay kapatılır)

Konferans

panel_app
POST /api/conference — en az 2 katılımcı (USER/INTERKOM/IP_HORN)
core
Benzersiz oda kodu üret → ConfBridge() extension'ı yaz → her katılımcıyı AMI Originate ile odaya çağır
confwatch
Odada tek kişi kalınca "yalnız kaldınız" anonsu çalar, 3 sn sonra çıkarıp odayı kapatır

7 panel-backend

Kiosk kullanıcısının systemd --user servisi (PipeWire soketine erişim için). :8090'da kimlik doğrulamasız yerel HTTP API.

audiowatch

udevadm monitor ile ses kartı tak/çıkar olaylarını dinler, wpctl status çıktısını parse edip cihaz listesini yayınlar.

internal/voip

Elle yazılmış SIP UA: tek kalıcı UDP soket, REGISTER + digest, INVITE/BYE/CANCEL işleme, Dial (giden çağrı), durum makinesi idle→ringing→dialing→active.

ses

arecord/aplay alt süreçleri, 20 ms çerçeve, G.711 μ-law kodek, RNVCS_MIC_GAIN (4×) yazılımsal kazanç.

HTTP uçları

/api/audio-devices, /api/volume (wpctl), /api/session, /api/call/{status,dial,answer,reject,hangup}.

Not fix_voip.py 2026-08-25'teki bir düzeltmeyi uygulayan tek seferlik yama; değişiklik zaten kaynakta, dosya artık işlevsiz.

8 panel-app

Tek dosya (~180 KB; ~92 KB'ı gömülü base64 arka plan görseli). Yapılandırma URL ile: ?panel=…&core=…&backend=…&demo.

  • VoIP sekmesi: dialpad, hızlı arama (Platformlar / Merkezler / IP Horn filtreleri, 8'li sayfalama).
  • Telsiz sekmesi: statik görsel, işlevsiz (önizleme).
  • Sayfam sekmesi: 9×6 kutu, uzun basışla menü (etiket/taşıma/silme/bilgi); sunucuda sayfam_tiles olarak saklanır.
  • Oturum sessionStorage'da; dil TR/AZ/EN; ekran klavyesi; sesli mesaj 30 sn'de bir yoklanır.
İkiz dosya panel_app.html ve panel_app_3_1.html birebir aynı — tek fark CORE varsayılan adresi. İkisini tutmak yerine ?core= parametresiyle çözmek yeterli.

10 Kurulum & dağıtım

İlk kurulum (CORE'da, sırayla)

sudo bash scripts/core_kurulum.sh        # Asterisk, PostgreSQL, ODBC, Redis, ufw
sudo bash scripts/core_migrate.sh        # şema (migration'lar sırayla)
cd core && sudo bash install_yonetim_servisi.sh   # derle, kur, ilk admin

Panelde: cd panel-backend && bash install_servis.sh (kiosk kullanıcısı, sudo'suz).
